# 🔒 محافظت صفحات سازمانی

**تاریخ**: 2025-11-10  
**تغییر**: افزودن محافظت برای صفحات `OrganizationProfile` و `OrganizationContract`

---

## 🎯 مشکل قبلی

کاربران **قبل از لاگین** می‌توانستند به صفحات تکمیل اطلاعات سازمانی دسترسی داشته باشند:
- ❌ کاربر لاگین نکرده → می‌تونست OrganizationProfile ببینه
- ❌ کاربر فردی → می‌تونست OrganizationProfile ببینه
- ❌ هیچ چکی روی نوع کاربر نبود

---

## ✅ راه‌حل

### 1. ایجاد Protected Components

```javascript
// 🔒 فقط کاربران سازمانی لاگین شده
const ProtectedOrganizationProfile = withOrganizationAccess(OrganizationProfileScreen, {
  allowOrganizationAccess: true,
  requireCompleteAccess: false, // نیازی به تایید کامل نیست
  customAccessCheck: ({ isOrganizationUser }) => {
    if (!isOrganizationUser) {
      return {
        allowed: false,
        title: "دسترسی محدود",
        message: "این بخش فقط برای کاربران سازمانی است.",
        showRetry: false
      };
    }
    return { allowed: true };
  }
});
```

### 2. استفاده در Navigation

```javascript
<Stack.Screen 
  component={ProtectedOrganizationProfile} // ✅ Protected
  name="OrganizationProfile" 
  options={{ headerShown: false }} 
/>
```

## 📋 رفتار جدید

| وضعیت کاربر | دسترسی به OrganizationProfile | دسترسی به OrganizationContract |
|------------|-------------------------------|--------------------------------|
| لاگین نکرده | ❌ صفحه محدودیت | ❌ صفحه محدودیت |
| کاربر فردی | ❌ صفحه محدودیت | ❌ صفحه محدودیت |
| کاربر سازمانی (تایید نشده) | ✅ دسترسی آزاد | ✅ دسترسی آزاد |
| کاربر سازمانی (تایید شده) | ✅ دسترسی آزاد | ✅ دسترسی آزاد |

## 🔐 منطق امنیتی

1. **چک اول**: آیا کاربر لاگین کرده؟
   - اگر نه → صفحه محدودیت با پیام "لطفا وارد شوید"

2. **چک دوم**: آیا کاربر سازمانی است؟
   - اگر نه (کاربر فردی) → صفحه محدودیت با پیام "فقط برای کاربران سازمانی"
   - اگر بله → ✅ دسترسی آزاد

3. **هیچ چک تایید**: 
   - کاربر سازمانی تایید نشده هم می‌تونه این صفحات رو ببینه
   - چون هدف این صفحات همین تکمیل اطلاعات برای تایید است!

## 🧪 تست سناریوها

### ✅ سناریو 1: کاربر لاگین نکرده
```
1. کاربر روی لینک OrganizationProfile میره
2. سیستم چک می‌کنه: isAuthenticated = false
3. نمایش: صفحه محدودیت با پیام "لطفا وارد شوید"
```

### ✅ سناریو 2: کاربر فردی لاگین کرده
```
1. کاربر فردی روی لینک OrganizationProfile میره
2. سیستم چک می‌کنه: userType = 'individual'
3. نمایش: صفحه محدودیت با پیام "فقط برای کاربران سازمانی"
```

### ✅ سناریو 3: کاربر سازمانی تایید نشده
```
1. کاربر سازمانی (pending) روی OrganizationProfile میره
2. سیستم چک می‌کنه: userType = 'organization'
3. نمایش: ✅ صفحه OrganizationProfile (می‌تونه اطلاعاتش رو تکمیل کنه)
```

### ✅ سناریو 4: کاربر سازمانی تایید شده
```
1. کاربر سازمانی (approved) روی OrganizationProfile میره
2. سیستم چک می‌کنه: userType = 'organization'
3. نمایش: ✅ صفحه OrganizationProfile (می‌تونه اطلاعاتش رو ویرایش کنه)
```

## 💡 نکته مهم

این صفحات **نیاز به تایید کامل ندارند** (`requireCompleteAccess: false`) چون:
- هدفشون همین تکمیل اطلاعات برای تایید است
- کاربر تایید نشده باید بتونه اطلاعاتش رو اصلاح کنه
- اگر تایید کامل می‌خواستیم، کاربر در یک loop گیر می‌کرد!
